## 무슨 일이 있었나

예전에는 집에 있는 미니 PC에 워드프레스를 올려서 블로그를 운영했다. 간단한 글도 꽤 올렸었다. 그런데 설정을 한 번 잘못 건드린 뒤로 글이 전부 사라졌다. 백업은 없었다. 그 뒤로 한동안 블로그를 다시 할 마음이 들지 않았다.

그전부터 불편한 신호도 있었다. 서버에 봇이 계속 들어와 두드려 댔고, 로그를 볼 때마다 진저리가 났다.

## 원인

- 글이 서버의 DB 안에만 있었다. DB가 망가지면 글도 같이 사라지는 구조였다.
- 백업이 없었다.
- 블로그 하나를 위해 서버, PHP, 플러그인, 공유기 포트까지 직접 관리하고 있었다. 관리할 게 많을수록 망가질 곳도 많았다.

## 바꾼 것

- **글을 Git에 둔다.** 이제 글 하나가 마크다운 파일 하나고, 저장소가 곧 백업이다. 설정을 망가뜨려도 이전 커밋으로 돌아가면 된다.
- **서버를 운영하지 않는다.** Astro로 정적 사이트를 만들고, push하면 Cloudflare가 빌드해서 배포한다. 열어 둘 포트도, 패치할 플러그인도 없다.

## 다시 만들면서 막힌 것

### 첫 배포 실패

Cloudflare에서 프로젝트를 만들었는데 프레임워크를 고르는 칸이 보이지 않았고, 배포는 실패했다. 알고 보니 Pages가 아니라 Workers 쪽 화면으로 만든 것이었다. Workers는 빌드한 뒤 `wrangler deploy`로 올리는데, 저장소에 무엇을 올릴지 적힌 설정이 없었다. `wrangler.jsonc`에 빌드 결과인 `dist/`를 정적 자산으로 올리라고 적어 주자 해결됐다.

### 도메인이 계속 Pending

`woosupar.dev`는 Porkbun에서 샀다. Cloudflare에 도메인을 추가하면 Pending 상태가 되는데, 등록기관에서 네임서버를 Cloudflare로 바꾸고 그게 확인될 때까지 계속 그 상태다. Porkbun에서 네임서버를 바꾸고 나서야 Active로 넘어갔다.

### 예전 DNS 레코드

도메인을 옮기니 Porkbun 시절 레코드가 그대로 따라왔다.

| 레코드 | 가리키던 곳 |
|---|---|
| `woosupar.dev` A | 집 IP (예전 워드프레스 서버) |
| `*.woosupar.dev` CNAME | Porkbun 주차 페이지 |
| `www.woosupar.dev` CNAME | `ghs.google.com` |

첫 줄을 보고 좀 놀랐다. 도메인이 집 IP를 그대로 가리키고 있었다. 봇이 몰려왔던 것도 아마 이 때문이었을 것이다. 세 개 모두 지웠다.

### Route와 Custom domain

Worker에는 `*.woosupar.dev/*` Route가 걸려 있었는데, 이걸로는 사이트가 열리지 않았다. 이유는 두 가지였다.

- `*`는 서브도메인만 뜻한다. `woosupar.dev` 자체는 포함되지 않는다.
- Route는 DNS 레코드를 만들어 주지 않는다. 주소록에 항목이 없으면 요청이 Worker까지 오지도 않는다.

Custom domain으로 `woosupar.dev`를 추가하자 Cloudflare가 레코드와 인증서를 같이 만들어 줬고, 그제야 열렸다.

## 정리

DNS가 볼 때마다 복잡했던 건 역할이 여러 층으로 나뉘어 있어서였다.

```
Porkbun          도메인의 주인. 주소록 담당자를 지정한다 (네임서버)
Cloudflare DNS   주소록. 이름을 어디로 보낼지 정한다 (레코드)
Cloudflare 엣지  HTTPS, 캐시, 봇 차단 (프록시)
Worker           실제로 HTML을 돌려준다
```

막혔던 문제마다 어느 층의 일인지 따져 보니 훨씬 덜 헷갈렸다.
